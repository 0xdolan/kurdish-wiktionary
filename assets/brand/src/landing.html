Structured the way the wiki is

Each wiki page nests language, then part of speech, then subsections. The dataset keeps that tree and gives each section type its own table.

Use it the way you work

Parquet, CSV and JSONL for code. Excel for browsing. SQLite and PostgreSQL for queries. MDX and MDD for GoldenDict and MDict.

Start in one minute

import pandas as pd

entries = pd.read_parquet("parquet/entries.parquet")
senses = pd.read_parquet("parquet/senses.parquet")

kurmanci = entries[entries.language_code == "ku"]
kurmanci.merge(senses, on="entry_id").query("title == 'heval'")[["pos", "definition"]]

Know the limits

  • {{auto_pct}}% of entries are marked bot-made from translation tables, and the wiki warns they may contain errors. They are flagged, so you can leave them out.
  • Many entries are thin: a one-line gloss or an inflected form. Of {{stat_kurmanci}} Kurmancî entries, {{kurmanci_headwords}} are headwords with a definition.
  • Recordings are mostly not Kurdish. About {{audio_kurmanci}} are Kurmancî. The rest are largely English, German and French.
  • Extraction is heuristic. The wiki is written by hand, so expect some oddities. Every release ships a quality report.
  • Media licences vary per file. Check the media table before reusing a recording or image.
